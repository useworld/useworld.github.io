    요약

    CVE-2026-123039은 Check Point Gaia의 DynamicCLI daemon을 통해 로컬 프로세스가 root 권한으로 명령을 실행할 수 있는 취약점이다. root로 실행되는 dynamic_server가 제어 소켓을 모든 사용자에게 쓰기 가능한 상태로 제공하고, 연결한 프로세스의 인증·인가를 수행하지 않는 구조가 핵심이다. PHP2Shell로 포털 프로세스 실행 권한을 얻은 공격자가 이 취약점을 연결하면 게이트웨이의 root 권한까지 확보할 수 있다.

    checkpoint-gaia-scanner는 Check Point의 2026-11-12 advisory인 sk1000362를 기준으로 수정된 Jumbo Hotfix Take를 제시한다. 점검 시에는 설치된 Take와 함께 /tmp/dynamic_socket의 실제 권한, daemon 실행 상태를 확인한다.

    취약 지점과 실행 조건

    DynamicCLI는 제한된 clish에서 expert-mode 진단 명령을 사용할 수 있도록 연결하는 기능이다. 요청을 처리하는 /usr/bin/dynamic_server는 root로 실행되며, 로컬 AF_UNIX 소켓 /tmp/dynamic_socket을 사용한다.

    두 공개 저장소가 설명하는 취약 지점은 다음과 같다.

    항목 동작
    제어 소켓 /tmp/dynamic_socket
    취약한 접근 권한 0777로 생성돼 일반 로컬 프로세스도 연결 가능
    호출자 검증 연결 프로세스에 대한 인증·인가 누락
    요청 형식 #<length># <command> 형태의 명령 문자열
    실행 권한 요청을 받은 daemon의 root 권한
    관련 로그 /var/log/dynamicCli.log

    공격에는 장비 내부에서 프로세스를 실행할 수 있는 발판이 필요하다. 포털 worker나 서비스 계정처럼 낮은 권한으로 실행되는 프로세스도 이 조건에 들어간다. 취약 소켓에 접근한 프로세스는 root daemon에 명령 실행을 위임하는 primitive를 얻는다.

    이 소켓은 로컬 IPC 인터페이스다. 외부에서 소켓으로 직접 접속하는 경로가 아니라, 포털 침해 등으로 얻은 초기 실행 권한을 root 권한으로 확장하는 단계에 해당한다.

    코드 분석

    재현 모델의 의미

    googlesky/CVE-2026-123039은 취약 동작과 수정 동작을 비교하는 컨테이너 기반 재현 모델이다. 실제 Gaia의 dynamic_server 바이너리나 벤더 patch를 배포하는 저장소는 아니다. 따라서 모델에서 구현한 검증 로직을 제품의 실제 patch diff로 해석해서는 안 된다.

    재현 대상은 명확하다. 일반 로컬 프로세스가 쓰기 가능한 소켓에 명령을 전달하고, 호출자를 검증하지 않는 root daemon이 이를 실행하는 경로다.

    탐지 도구 실행

    출처: foxcornlab — checkpoint-gaia-scanner

    python3 checkpoint_gaia_scanner.py --local

    이 명령은 게이트웨이의 expert mode에서 실행하는 로컬 점검 방식이다. 도구는 cpinfo의 버전 정보, 제어 소켓 권한, daemon 상태를 읽고 /var/log/dynamicCli.log의 존재 여부를 보고한다. exploit 요청을 보내는 기능은 없으며, 판정은 설치 정보와 로컬 상태에 기반한다.

    DynamicCLI 중지

    출처: googlesky — CVE-2026-123039

    dbset process:dynamic_server off
dbset :save

    저장소가 제시하는 벤더 완화 명령으로, expert mode에서 dynamic_server를 중지하고 설정을 저장한다. 명령을 수신하는 daemon을 내려 취약 경로를 차단하지만 DynamicCLI 기능도 중단된다. 취약 코드를 수정하는 patch 적용과는 구분해야 한다.

    탐지와 대응

    네트워크

    DynamicCLI 요청은 로컬 AF_UNIX 소켓을 통과하므로 일반적인 네트워크 패킷 기록만으로 권한 상승 단계를 추적하기 어렵다. 포털 침해 시점의 외부 요청과 이후 게이트웨이에서 발생한 내부 접속을 시간순으로 연결한다.

    탐지 도구 README는 게이트웨이에서 내부 VMware 호스트로 향하는 비정상 SSH와 방화벽 로그 공백을 조사 항목으로 제시한다. SSH 기록에서는 출발 장비, 사용 계정, 대상 호스트와 접속 시각을 대조한다.

    엔드포인트

    핵심 점검 대상은 /tmp/dynamic_socket과 /usr/bin/dynamic_server다. 탐지 도구는 소켓 권한 0777을 노출 징후로, 0660을 수정 후 기대 상태로 설명한다.

    버전 정보만으로 점검을 끝내지 않는다. 수정된 Take가 표시돼도 소켓이 계속 0777이라면 실제 실행 상태에 수정이 반영됐는지 확인한다. 예상하지 못한 CPconfigdaemon 프로세스도 함께 조사한다.

    서버

    /var/log/dynamicCli.log는 daemon이 수락한 요청을 추적하는 경로다. 요청 시각과 포털 프로세스의 실행 흔적을 대조하고, 요청에 포함된 명령이 만든 프로세스와 파일을 연결한다.

    ESXi 측에서는 게이트웨이를 출발점으로 하는 SSH 세션과 해당 세션 이후의 작업 기록을 조사한다. 방화벽 로그 공백이 보이면 외부로 전송된 로그와 대상 서버의 기록을 함께 비교한다.

    patch 적용 기준

    checkpoint-gaia-scanner가 2026-11-12 Check Point advisory sk1000362를 근거로 제시한 수정 기준은 다음과 같다.

    Gaia 릴리스 수정된 Jumbo Hotfix Take
    R82.20 Take 14 이상
    R82.10 Take 52 이상
    R82 Take 132 이상
    R81.20 Take 174 이상

    릴리스 이름만으로 적용 여부를 판단할 수 없다. expert mode에서 다음 명령을 실행하고 HOTFIX_..._JUMBO_HF_MAIN 항목의 Take를 확인한다.

    cpinfo -y all

    탐지 도구는 R82.20 Take 11–13, R82.10 Take 51, R82 Take 131을 수정 완료로 판정하지 않는다. advisory가 명시한 수정 Take 이상인지 확인하고, 적용 후 소켓 권한과 daemon 상태를 다시 점검한다.

    patch와 침해 흔적 점검

    patch 적용은 이미 실행된 명령이나 배치된 파일을 제거하지 않는다. /var/log/dynamicCli.log, 비정상 프로세스, 게이트웨이에서 내부 서버로 이어진 접속 기록을 함께 조사한다.
