    요약

    Fragnesia는 Linux 커널의 소켓 버퍼 병합 과정에서 공유 프래그먼트 표시가 유실되는 로컬 권한 상승 취약점이다. skb_try_coalesce()가 파일 페이지를 참조하는 프래그먼트를 옮기면서 SKBFL_SHARED_FRAG를 전달하지 않아, ESP 복호화가 페이지 캐시를 직접 덮어쓸 수 있다. Ubuntu 보안 공지의 공개일은 2026-05-23이다.

    공격에는 로컬 코드 실행과 관련 커널 경로에 접근할 수 있는 환경이 필요하다. 공개 PoC는 읽기 전용 파일의 페이지 캐시 변조를 이용하며, PAN-OS 관리 인터페이스 공격을 다루지 않는다.

    취약 지점

    skb_try_coalesce()는 원본 소켓 버퍼의 페이지 프래그먼트를 대상 버퍼로 옮긴다. 이때 페이지 참조는 유지되지만 공유 상태 표시가 빠지면, 대상 버퍼는 페이지 캐시를 참조하면서도 공유 프래그먼트가 없는 것처럼 보인다.

    ESP 입력 경로는 skb_has_shared_frag()를 검사해 skb_cow_data() 호출 필요성을 판단한다. 표시가 유실된 버퍼에서는 복사 없이 기존 페이지에 복호화 결과를 쓸 수 있다.

    항목 내용
    취약 함수 skb_try_coalesce()
    관련 경로 XFRM/ESP-in-TCP, espintcp ULP
    유실되는 표시 SKBFL_SHARED_FRAG
    후속 판단 지점 skb_has_shared_frag()
    우회되는 보호 처리 skb_cow_data()를 통한 데이터 복사
    공격자가 얻는 쓰기 능력 읽기 가능한 파일의 페이지 캐시 바이트 변조

    공개 PoC는 splice()로 파일 페이지를 TCP 경로에 연결하고, 제어한 AES-GCM 복호화 결과를 이용한다. Ubuntu 커널 패치 설명도 이 경로를 통한 읽기 전용 파일 변조와 로컬 권한 상승을 설명한다.

    PoC 분석

    출처: V12 Security의 fragnesia.c

        ret = splice(fd, &off, p[1], NULL, FRAG_LEN, 0);
    if (ret != FRAG_LEN)
        die("sender splice file to pipe");

    ret = splice(p[0], NULL, sock, NULL, FRAG_LEN, 0);
    if (ret < 0)
        die("sender splice pipe to tcp");

    송신 측은 대상 파일의 페이지를 파이프를 거쳐 TCP 소켓으로 전달한다. 수신 측은 데이터가 대기열에 들어간 뒤 TCP_ULP를 espintcp로 설정해 ESP 처리 경로로 넘긴다. 공유 표시가 유실되는 커널에서는 이 페이지가 복호화의 쓰기 대상이 될 수 있다.

    PoC 실행에는 사용자·네트워크 네임스페이스 생성과 내부 XFRM 설정이 필요하다. Ubuntu의 비특권 사용자 네임스페이스 제한처럼 이 설정을 막는 정책은 PoC 실행 조건에 영향을 준다.

    patch 분석

    2026-05-13 제출된 패치는 net/core/skbuff.c에서 페이지 프래그먼트를 전달할 때 공유 표시도 함께 전달하도록 바꾼다.

    출처: netdev 패치: preserve shared-frag marker during coalescing

    @@ -6200,6 +6200,8 @@ bool skb_try_coalesce(struct sk_buff *to, struct sk_buff *from,
           from_shinfo->frags,
           from_shinfo->nr_frags * sizeof(skb_frag_t));
    to_shinfo->nr_frags += from_shinfo->nr_frags;
+   if (from_shinfo->nr_frags)
+       to_shinfo->flags |= from_shinfo->flags & SKBFL_SHARED_FRAG;

    if (!skb_cloned(from))
        from_shinfo->nr_frags = 0;

    추가된 조건은 전달할 페이지 프래그먼트가 있을 때 원본의 SKBFL_SHARED_FRAG 비트를 대상에 합친다. 후속 ESP 처리는 이 표시를 보고 페이지를 직접 덮어쓰기 전에 복사 필요성을 판단할 수 있다. 바이트를 대상 버퍼의 선형 영역으로 복사하는 경로는 페이지 참조를 넘기지 않으므로 같은 처리가 필요하지 않다.

    완화와 관측 포인트

    배포판이 제공하는 수정 커널을 적용한다. 다음은 원본 저장소가 제시한 일반 Linux 환경용 임시 완화 명령이다.

    출처: Fragnesia 저장소의 임시 완화 명령

    sudo sh -c "printf 'install esp4 /bin/false\ninstall esp6 /bin/false\ninstall rxrpc /bin/false\n' > /etc/modprobe.d/fragnesia.conf"
sudo rmmod esp4 esp6 rxrpc 2>/dev/null || true

    첫 번째 명령은 지정 모듈의 modprobe 적재를 차단하는 설정을 쓴다. 두 번째 명령은 적재된 모듈 제거를 시도하지만 오류를 숨기므로, 설정 파일과 실제 모듈 적재 상태를 따로 점검해야 한다. ESP 모듈 비활성화는 이를 사용하는 IPsec 통신에 영향을 줄 수 있다.

    적용 범위

    이 명령은 일반 Linux 환경용 예시다. PAN-OS 장비에 적용하는 절차로 사용하지 않는다.

    조사 시에는 같은 프로세스 흐름에서 네임스페이스 생성, XFRM 설정, 파일에 대한 splice(), TCP_ULP의 espintcp 설정이 이어지는지 살핀다. 개별 호출만으로 공격을 판정하기보다 파일 접근과 네트워크 설정을 연결해 분석한다.

    페이지 캐시 변조는 디스크에 저장된 파일 내용과 구분해야 한다. 일반 파일 읽기 역시 페이지 캐시를 거칠 수 있으므로, 파일 해시만으로 변경이 디스크에 기록됐는지 판단하지 않는다.
