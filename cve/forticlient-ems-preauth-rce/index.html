    FortiClient EMS 사전 인증 원격 코드 실행 취약점(CVE-2026-35616) — 분석 및 대응 가이드

    2026-04-06 # Cve

    요약

    • FortiClient Enterprise Management Server(EMS)에 사전 인증 원격 코드 실행(CVE-2026-35616) 취약점이 공개되었고, 벤더가 핫픽스를 배포했으며(긴급 패치), 악용 정황이 보고되었습니다. (bleepingcomputer.com)
    • 공격자는 인증 없이 특정 관리용 API 엔드포인트를 이용해 권한 우회 및 원격 명령 실행을 시도할 수 있습니다(취약점은 접근 제어/인증 검증의 결함으로 설명됨). (thehackernews.com)
    • 영향을 받는 버전으로 보고된 범위는 FortiClient EMS 7.4.5 및 7.4.6이며, 벤더는 핫픽스 적용 또는 7.4.7로의 업그레이드를 권고했습니다. 인터넷에 노출된 EMS 인스턴스는 즉시 차단·패치가 필요합니다. (bleepingcomputer.com)

    Note

    본 문서는 운영자 관점에서 즉시 적용 가능한 점검·차단·패치 절차를 제시합니다. - 확인된 사실과 공지(공개 보도자료/보안 매체 보도)를 근거로 정리하였으며, 공개 자료에 명시되지 않은 기술적 세부사항은 명확히 표기합니다. - 본 문서를 따라 조치하되, 포렌식 확보 후 패치 및 재구성 작업을 병행하시기 바랍니다.

    영향 범위와 심각도

    • 제품: Fortinet FortiClient Enterprise Management Server (EMS)
    • 영향 버전(보고된 범위): FortiClient EMS 7.4.5, 7.4.6 (7.4.7에서 수정 예정 또는 핫픽스 제공). EMS 7.2 등 다른 메이저 라인은 보도에 따라 영향 여부가 다르므로 환경별 확인 필요. (bleepingcomputer.com)
    • 심각도: Critical / CVSS 상위권(보도상 예: 9.1로 보도됨). (thehackernews.com)
    • 악용 상태: 실제 악용(인-더-와일드) 보고(보안 연구자·위협 인텔 관찰치 기준). (thehackernews.com)
    • 잠재적 노출 자산: 인터넷 직접 노출된 EMS 인스턴스, 리버스 프록시·로드밸런서 뒤의 노출 경로, 관리망 분리가 미흡한 환경

    기술 분석 (요지)

    • 취약 유형: 사전 인증(pre-auth) API 접근 제어 우회 — 인증·권한 검증 생략 또는 회피 가능. (thehackernews.com)
    • 근본 원인(공개 자료 기반 요약): 특정 관리용 API 경로에서 인증·권한 검증이 불충분하거나 우회 가능성이 있으며, 입력 처리·직렬화 검증에 결함이 있어 임의 명령 실행으로 이어질 수 있음(보도 요약). (bleepingcomputer.com)
    • 공격 표면: EMS 웹관리 포트(기본 HTTPS), 리버스 프록시 경유 엔드포인트, 내부 자동화·CI/CD가 호출하는 EMS API
    • 재현·악용 조건(공개 관측 기반): EMS에 네트워크 접근이 가능하면 추가 인증 없이도 특정 요청으로 악용이 시도될 수 있음. 일부 공격은 특수 헤더·직렬화 페이로드 구성이 필요할 수 있음. (thehackernews.com)

    운영 영향(가능 시나리오)

    • 중앙 관리형 에이전트 정책 변조, 악성 소프트웨어 배포 경로로의 전환
    • 에이전트 업데이트 채널·배포 파이프라인 악용을 통한 랜섬웨어·C2 확산
    • 자격증명·토큰 탈취로 인한 추가 권한 상승 및 도메인 내 확산

    관측 가능한 지표(예시)

    • 웹 액세스 로그: 짧은 시간 다수의 특이한 POST/GET 요청, 비정상 User-Agent, 비정상 URI 탐색 시도
    • 인증 로그: 알 수 없는 관리자 계정 생성/변경 시도, API 토큰 사용 패턴 이상
    • 배포 로그: 정책·패키지 대량 배포 이력 급증
    • 호스트: EMS 호스트에서 비정상 프로세스 실행(cmd.exe, powershell, certutil, curl 등) 또는 새 서비스 설치 흔적

    예시 탐색 명령(Windows 환경): 

    # IIS/프록시 로그에서 의심 요청 검색
Select-String -Path "C:\inetpub\logs\LogFiles\W3SVC*\u_ex*.log" `
  -Pattern "POST /", "PUT /", "cmd=", "powershell", "curl", "Invoke-Expression"

# 프로세스 생성 이벤트 확인
Get-WinEvent -LogName Security | Where-Object {$_.Id -in 4688, 4672} | Select TimeCreated,Message

# 포트 노출 확인
netstat -ano | findstr ":443"

    즉시 대응 체크리스트

    네트워크 - 인터넷에 노출된 EMS 접근 차단(방화벽·ACL 적용).
    - 관리 포트는 전용 관리망 또는 VPN으로만 접근 허용.
    - WAF(있는 경우) 서명 적용 및 의심 URI/메서드 차단(임시 규칙).

    호스트·엔드포인트 - EMS 호스트의 전체 백업 및 포렌식 이미지 확보(조치 전).
    - 의심 프로세스·서비스 상시 모니터링 및 즉시 차단·격리.
    - 백업·배포 리포지토리의 무결성 확인(변조 여부 점검).

    인증·권한 - 관리자 계정 전수 점검 및 의심 계정 비활성화/비밀번호 강제 변경.
    - API 토큰과 서비스 계정 재발급(필요시 관련 세션·토큰 무효화).
    - AD 통합 환경에서는 고권한 계정 세션 및 티켓 무효화 고려.

    완화(패치 전) - 관리 UI/API를 외부에서 차단.
    - 리버스 프록시에서 위험 메서드·경로 임시 차단(필요 시 특정 파라미터 패턴 필터링).
    - 호스트 수준에서 불필요한 서비스 비활성화 및 접근 최소화.

    패치 후 검증 - 적용된 빌드·버전이 패치 노트와 일치하는지 검증. (bleepingcomputer.com)
    - 서비스 재기동 후 비정상 호출·재시도 모니터링 강화.
    - 패치 적용 로그와 포렌식 아티팩트(변조 흔적)를 비교 검토.

    권장 탐지 규칙(개요)

    • 웹 로그 기반 이상 탐지: 동일 IP가 짧은 시간 내 다양한 관리자 엔드포인트를 탐색하면 경보.
    • 프로세스 생성 체인 분석: EMS 서비스 프로세스 하위에 쉘·스크립트 인터프리터가 등장하면 고위험 알림.
    • 데이터 유출 감지: EMS 서버에서 대용량 외부 전송 발생 시 경보 및 차단.

    우선순위 로드맵(권장 일정)

    • 0일(긴급): 인터넷 노출 차단, 핫픽스 적용, 로그 보존 및 IOC(지표) 스윕. (bleepingcomputer.com)
    • 1–3일: 자격증명 교체, 정책·배포 체인 무결성 검토, 네트워크 세분화 강화.
    • 1주 이내: 관리망 분리, 다중 인증 도입, 최소 권한 원칙 적용 및 취약점 스캔 자동화.

    위험 평가와 권고 조치(요약)

    • 인터넷 노출 EMS — 위험도: 매우 높음
    • 즉시: 외부 차단, WAF/프록시 룰 적용
    • 장기: 전용 관리망 전환, 지속적 노출 스캐닝
    • 미패치 EMS — 위험도: 매우 높음
    • 즉시: 핫픽스 적용 또는 버전 업그레이드
    • 장기: 정기 패치 윈도우 운영
    • 자격증명 유출 우려 — 위험도: 높음
    • 즉시: 비밀번호·토큰 교체, 세션 무효화
    • 장기: PAM/비밀관리 도입
    • 로깅·모니터링 미흡 — 위험도: 중간
    • 즉시: 감사 로그 보존 정책 강화
    • 장기: 중앙 SIEM 연동·상관분석 구현

    남은 불확실성(공개 정보 기준)

    • 익스플로잇에 사용되는 구체적 페이로드와 취약 경로의 상세 구현은 공개 범위가 제한적입니다.
    • 일부 환경·구성에 따라 재현 조건이 상이할 수 있습니다.
    • 벤더가 영향 버전 목록을 추가·수정할 가능성이 있으므로 패치 노트와 공식 공지를 수시 확인해야 합니다. (bleepingcomputer.com)

    배경(관련 과거 사건)

    • 본 취약점은 최근 공개되어 활발히 악용되는 또 다른 FortiClient EMS 취약점(CVE-2026-21643)과 시기적으로 가깝게 보고된 사례들 가운데 하나입니다. 이전 취약점도 실제 악용이 관측된 바 있어, EMS 관련 노출과 패치 관리는 우선순위가 높습니다. (bleepingcomputer.com)
