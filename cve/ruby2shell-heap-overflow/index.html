    요약

    CVE-2026-132825는 Ruby가 특정 비 UTF-8 인코딩 문자열의 대소문자를 변환할 때 발생하는 1바이트 힙 버퍼 오버플로다. Ruby 공식 보안 권고문은 2026-11-19 공개됐으며, 수정 버전은 3.3.14, 3.4.13, 4.0.10이다. 공격자가 제어하는 문자열이 취약한 변환 경로에 도달하면 메모리 손상이나 프로세스 충돌이 발생할 수 있고, 일부 조건에서는 원격 코드 실행으로 이어질 수 있다.

    항목 내용
    CVE CVE-2026-132825
    통칭 Ruby2Shell
    취약 지점 특정 단일 바이트 인코딩의 문자열 대소문자 변환
    취약점 유형 출력 버퍼 끝을 넘어서는 1바이트 쓰기
    직접 영향 힙 메모리 손상, 프로세스 충돌
    조건부 영향 Ruby 프로세스 권한으로 원격 코드 실행

    취약 경로와 악용 조건

    ISO-8859-1이나 Windows-1252 같은 단일 바이트 인코딩에서 대소문자를 변환하면 일부 문자의 출력 길이가 늘어난다. 취약한 변환 로직은 이 과정에서 출력 버퍼 끝을 넘어 1바이트를 쓸 수 있다.

    Red Hat 권고문은 관련 경로로 upcase·upcase!, swapcase·swapcase!, :fold 옵션을 사용하는 downcase·downcase!, casecmp?를 명시한다. 대응하는 Symbol 메서드도 영향을 받는다. 일반 downcase 호출까지 같은 조건으로 묶어서는 안 된다.

    공격 경로가 성립하려면 공격자가 문자열 내용과 인코딩에 영향을 줄 수 있고, 해당 문자열이 취약한 대소문자 변환에 전달돼야 한다. 웹 서비스에서는 요청 입력이 Ruby 문자열로 만들어진 뒤 인코딩이 지정되고 변환 메서드가 호출되는 흐름을 살펴야 한다. HTTP Content-Type의 charset 선언만으로 내부 문자열의 인코딩을 판단할 수는 없다.

    원격 코드 실행 조건

    1바이트 경계 밖 쓰기는 인접한 힙 데이터를 손상시키는 수단이다. 원격 코드 실행에는 손상 대상과 힙 배치를 이용하는 추가 조건이 필요하다. Ruby 개발진은 일부 조건에서 원격 코드 실행을 입증한 개념 증명을 명시했다.

    코드 분석

    출처: Ruby2Shell 공개 저장소 README

    "ß".upcase
# => "SS"

    String#upcase가 문자 하나를 두 문자로 확장하는 예시다. 취약점의 핵심은 확장된 결과를 기록할 때 출력 버퍼 경계를 지키는 데 있다. 이 코드는 비 UTF-8 인코딩을 지정하지 않으므로 오버플로 재현 코드로 볼 수 없다.

    영향 범위와 수정 버전

    Ruby 공식 권고문과 보안 공지가 제시한 버전 범위는 다음과 같다.

    Ruby 계열 영향 버전 수정 버전
    3.3 3.3.13 이하 3.3.14
    3.4 3.4.0–3.4.12 3.4.13
    4.0 4.0.0–4.0.9 4.0.10

    서비스가 실제로 사용하는 Ruby 런타임을 수정 버전 이상으로 교체한다. Rails나 개별 젬만 갱신해서는 런타임의 메모리 처리 문제가 해결되지 않는다. 컨테이너는 수정된 런타임을 포함하도록 이미지를 다시 빌드하고 배포한 뒤 Ruby 프로세스를 재시작한다.

    Ruby 3.2 이하는 지원이 종료돼 상위 프로젝트의 수정 대상에서 제외됐다. 배포판 패키지는 보안 수정 역이식 여부를 해당 배포판 권고문으로 판단한다.

    점검과 대응

    외부 입력이 upcase, swapcase, downcase(:fold), casecmp?로 전달되는 호출 지점을 점검한다. 특히 force_encoding으로 인코딩을 지정한 뒤 변환하는 흐름에서는 입력 바이트와 실제 문자열 인코딩을 함께 살핀다.

    Ruby 프로세스의 비정상 종료 기록과 충돌 덤프를 입력 처리 시점에 연결한다. 충돌 직전의 입력, 문자열 인코딩, 대소문자 변환 호출은 취약 경로를 좁히는 단서다. 레거시 인코딩 사용이나 charset 선언만으로 공격을 판정하지 않는다.

    UTF-8을 요구하는 경로는 입력의 유효성을 검사한다. 레거시 인코딩을 지원해야 한다면 명시적으로 UTF-8로 변환한 뒤 대소문자 처리를 수행한다. 입력 경로 제한은 임시 완화 조치이며, 근본 대응은 수정된 Ruby 런타임의 배포다.
