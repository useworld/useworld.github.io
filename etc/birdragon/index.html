    그림 하나로 게임을? Claude Design으로 만든 Birdragon RPG

    사이드 프로젝트를 진행할 때 가장 큰 제약은 구현까지 도달하는 시간이다. 아이디어는 충분하지만, 실제로 동작하는 결과물로 이어지는 과정은 길고 복잡하다.
    2026-04-22 # etc

    서론

    사이드 프로젝트를 진행할 때 가장 큰 제약은 구현까지 도달하는 시간이다. 아이디어는 충분하지만, 실제로 동작하는 결과물로 이어지는 과정은 길고 복잡하다.

    출발점은 단순한 마스코트 스케치 하나였다. 이를 Claude Design에 입력으로 제공하고, 해당 이미지를 기반으로 게임을 생성하는 실험을 진행했다.

    Birdragon RPG 플레이

    조작법

    게임 화면을 한 번 클릭하고나서 엔터키를 치면 시작된다.
    WASD/화살표 이동 · J 공격 · K 마법 · SPACE 대화 · I 메뉴

    결과적으로, 단순 컨셉 수준을 넘어 실제로 플레이 가능한 웹 RPG 프로토타입까지 도달했다.

    캐릭터 소개

    Birdragon은 새와 용의 특징을 결합한 캐릭터다. 용 뿔 두 개, 용의 꼬리, 새의 날개 그리고 둥글고 통통한 새의 몸을 가진다. 전체 색상은 따뜻한 갈색 계열로 통일했다.
    전에 만든 새용티콘에서 착안하여 내 이름에서 따온 캐릭터를 만들었다.

    세계관은 일상성과 마법이 혼합된 구조다. 캐릭터 자체는 친근하지만, 탐험과 전투를 수행할 수 있는 잠재력을 가진 존재로 설정했다.

    게임 설계

    장르는 탑다운 2D 액션 RPG다. 젤다 시리즈, 스타듀 밸리, 고전 JRPG UI처럼 만들었다. 플레이 타임은 5~10분 내외의 미니 RPG로 설계했다.

    플레이 루프는 다음과 같다.
    마을에서 NPC와 대화를 시작 → 숲 탐험 → 버섯 요괴 3마리 처치 → 여우 상인에게 마법검 획득 → 그림자 동굴에서 보스 Shadow Wyrm 처치 → 장로에게 귀환 후 종료.

    조작 체계:

    • 이동: WASD / 화살표
    • 공격: J (근접 슬래시)
    • 스킬: K (파이어볼, MP 3 소모)
    • 대화: SPACE
    • 메뉴: I

    주요 시스템:

    • HP / MP / XP 기반 성장 구조
    • 레벨업 시 스탯 증가
    • 골드 및 상점 시스템
    • 크리티컬, 넉백, 피격 무적 처리
    • 보스 HP 바 및 데미지 숫자 팝업
    • 화면 흔들림 효과

    기술 스택 / 구조

    구현은 단순성을 최우선으로 설계했다.

    • HTML + CSS + Vanilla JavaScript
    • 외부 라이브러리 없음
    • SVG 기반 hand-drawn sprite
    • 타일맵: 40×28, 32px tile

    폰트는 Press Start 2P와 DotGothic16을 사용하여 도트 기반 JRPG 감성을 유지했다. 전체 시스템은 단일 HTML 파일로 구성되어 있으며, 별도 빌드 과정 없이 실행 가능하다.

    Claude로 개발한 과정

    개발 과정은 다음과 같이 진행되었다.
    스케치를 입력으로 제공 → Claude가 장르, 세계관, 분량에 대한 질문 생성 → 응답 기반으로 게임 구조 생성.

    이후 타일맵, sprite 구조, 전투 시스템, 대화 시스템이 일괄 생성되었다. 이후 반복적인 수정 과정을 통해 세부 완성도를 개선했다.

    특히 자연어 기반 수정이 가능하다는 점이 핵심이다. “타격감을 강화”, “JRPG 스타일 UI 강화”와 같은 요청이 빠르게 반영되었다.

    전통적인 방식에서는 엔진 학습, 에셋 제작, 구조 설계가 선행되어야 한다. 본 접근 방식은 이러한 초기 비용을 크게 축소한다.

    제작 시

    초기 단계에서는 완성도를 높이기보다 빠르게 실행 가능한 형태를 만드는 것이 중요하다. 방향성이 명확할수록 결과물이 빠르게 완성된다.

    전통적 방식 vs Claude 개발

    항목 전통적 방식 Claude 활용
    기획 문서 기반 설계 후 구현 대화 기반 즉시 구조화
    아트/스프라이트 직접 제작 또는 외부 구매 스케치 기반 생성
    코드 작성 수동 구현 자동 생성 후 보정
    반복 수정 비용 높음 자연어 기반 반복
    소요 시간 수개월~수년 수분~수시간
    러닝커브 엔진 및 툴 학습 필요 비교적 낮음

    AI 개발 도구의 발전 방향 고찰

    그러나 한계도 존재한다. 일단 개발 베이스 없이는 대화형으로 정확한 수정이 힘들다.
    그리고 대규모 시스템 설계, 세밀한 밸런싱 및 최적화는 여전히 AI로 전부 하기는 힘들다.
    결국 다루는 사람이 제대로 알아야 한다.

    결론

    이 모든게 딸깍 10분 컷이다. AI 미쳤다.
